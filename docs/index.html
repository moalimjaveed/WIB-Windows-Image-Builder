WIB: Windows Image Builder

A manifest-driven PowerShell engine for offline Windows 11 image customization. Built on native DISM and offline registry tooling — zero opaque third-party binary wrappers.

Quick Start Architecture & Features

Why Windows Image Builder?

Most Windows debloating scripts run undocumented registry commands directly on a live system, risking bricked OS updates, broken dependencies, and irreversible configuration drift. WIB operates offline on the official installation media before setup.

🛡 Isolated Offline Servicing

Mounts and modifies target WIM files inside isolated temporary mount points using native Microsoft tools (dism.exe, oscdimg.exe). Zero configuration changes to your live host operating system.

📝 Scoped Rollback Journals

Registry modifications generate an in-image undo journal (journal.reg and journal.json) for post-installation inspection and reversal via WibPanel.ps1.

🔒 Handle-Bound File Security

Employs kernel handle-bound deletions and strict DACL verification on sensitive manifests and recovery ledgers to defend against concurrent path redirection and unowned file substitution.

Quick Start

WIB requires Windows 10/11 x64, PowerShell 5.1 or 7.4+, and an elevated Administrator prompt for image mounting.

1. Validate and Dry-Run (Preview Plan)

The plan command mounts the image in a temporary workspace, catalogs packages and features, and generates a preview report without modifying the source media:

# Elevated Administrator session
.\build.ps1 `
  -IsoPath "C:\ISOs\Win11_26H2_English_x64.iso" `
  -ProfileName balanced `
  -Command plan

2. Build Custom Media

# Elevated Administrator session
.\build.ps1 `
  -IsoPath "C:\ISOs\Win11_26H2_English_x64.iso" `
  -ProfileName balanced `
  -OutputIso "C:\Images\Win11_Custom_Balanced.iso" `
  -ExpectedIsoSha256 "<KNOWN_MICROSOFT_SHA256>"

Security & Operational Boundaries

  • Unattended Credentials Notice: Microsoft Windows Setup answer file passwords are Base64 obscured, not encrypted. Anyone with read access to the installation media can decode them. Always use unique, temporary credentials.
  • Hash Integrity vs. Provenance: The -ExpectedIsoSha256 parameter verifies cryptographic file integrity against the digest you provide. Authenticity requires independently verifying the hash against official Microsoft release publications.
  • No Third-Party Executables: WIB runtime relies exclusively on official Microsoft Windows components (dism.exe, reg.exe, oscdimg.exe).
  • Windows PowerShell 5.1 Strictly Maintained: Engineered for enterprise compatibility without requiring external module installations.
